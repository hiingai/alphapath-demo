## 0. 一句话结论

> 对话里说了身份、入境时间、工作方式之后，Agent **自己判断"够不够出报告"**：不够就一次问一个**点一下就能答**的小问题（每条 ≤30 字、4 个选项），够了就按档案生成一份
> **84 个月（7 年）逐月排期**的 HTML 报告：签证分段、每次续签的准备与递交月、受雇/自雇双路径材料、强积金与报税、银行流水规矩、7 条风险（分高中低）与材料清单；
> 报告在浏览器里直接打开，也能一键下载成**离线可开、可打印**的 HTML。**全文没有任何"你能不能批"的结论**，只给排期、材料与风险。

## 1. 交互流程（用户只看到三步）

```
用户说一句「我是高才B类，带 2 个孩子读中二」
        │
        ├─ learnProfile() 写入档案：identityType=TTPS_B、dependants=2、schoolStage=中二
        ├─ AP.Plan.gaps() → 缺 activationDate、employment
        └─ 本轮结束后 500ms → 主动卡片：
             「还差 2 项就能生成 84 个月规划 —— 首次签证哪个月生效？」
             [这个月] [约6个月前] [约1年前] [约2年前] [稍后再填]
                       │ 点一下（同时把体检到的事实写进档案，不依赖正则）
                       ▼
             下一轮再问「接下来打算怎么受雇还是自雇？」→ [受雇][自雇][还没定]
                       │
                       ▼
             信息齐 → 档案页「信息齐全，可生成」→ 生成 → 新标签页打开报告 + 聊天里留一张卡（打开/下载）
```

**为什么要点选而不是让用户打字**：手机上一句话打完要 10 秒以上，点一下 1 秒；而且点选的值是**枚举**，
不会因为用户写"去年九月"而解析失败。用户也可以无视卡片直接打字，`learnProfile` 照样会抽。

**什么时候不打扰**：每轮最多问一次；一次会话最多问 4 次；有"稍后再填"；连问 2 次没回应就不再加。

## 2. 引擎：`engine/plan.js`

| 能力 | 说明 |
|---|---|
| `gaps(facts)` | 还缺哪些字段（必需：身份类型 / 首次激活日 / 工作方式） |
| `quickAsk(facts)` | 为缺的字段生成**一个问题 + 3–5 个选项**（每个选项带要写回的事实值与一句自然语言） |
| `build(facts)` | 生成完整报告数据（纯函数，同一档案永远同一结果） |
| `toHtml(plan)` | 生成**自包含** HTML（内联 CSS + 内联下载脚本，零外链，可离线/可打印） |
| `segments(identity)` | 从知识库取首次年期与续签串，算出覆盖 84 个月的签证分段 |

**签证分段不是写死的**：从 `AP_KB.identityTypes` 读 `first_years` 与 `renew`（如 `2+3+3`），累加到 84 个月为止。
所以政策一变，改知识库就够，不需要动报告代码。

**排期不是模板填空**：每个月都按"日历月份 + 处于哪个签证段 + 距离下个续签还有几个月 + 是否有子女"四条规则合成，
所以 4 月一定是报税、5 月一定核强积金、9 月一定有学籍（有孩子时）、续签前 4 个月一定开始备料、第 82 个月一定递永居。

## 3. 报告里到底有什么

| 章节 | 内容 |
|---|---|
| 封面 | 身份、起算月、目标（永居申请月）、规则版本、知识库指纹、build、生成时间 |
| 1 结论摘要 | 84 个月区间、几个签证段、主路径、风险条数与高风险数、强积金金额 |
| 2 签证分段 | 每段覆盖 M?a–M?b，首段/续签段性质 |
| 3 双路径 | **受雇**与**自雇**各 6 步（何时做什么、留什么材料），主路径高亮，附切换路径的注意点 |
| 4 钱 | 强积金规则（5%、下限 7,100、上限 30,000 → 最高 1,500/月，自雇按年）、三档收入估算表、报税口径、银行流水五条规矩、3–6 个月结余建议 |
| 5 84 个月排期 | 84 行表格：月序号、年月、阶段（落地/扎根/稳定/冲刺）、签证状态、本月动作 + 材料 + 风险；**黄底=续签准备月，绿底=续签递交月** |
| 6 风险评估 | 7 条，分高/中/低：为什么发生、怎么补 |
| 7 材料清单 | 8 类材料：为什么需要、什么时候准备 |
| 8 依据与免责 | 4 条：不构成审批结论、政策会变、金额为估算、规则版本可追溯 |

**风险清单（7 条，按档案动态增减）**
1. 「通常居住」连续性被质疑（高）
2. 自雇被认定为空壳公司（高，仅自雇）/ 雇主变动未报备（中，仅受雇）/ 路径未定材料空转（中，未填）
3. 强积金断供或漏供（中）
4. 银行流水与报税收入不一致（中）
5. 子女学籍中断（低，仅有受养人时）
6. 收入偏低需额外说明（中，月收入 < 20,000 时）
7. 错过续签递交窗口（高）、材料真实性（高）

## 4. 红线怎么守的

| 红线 | 做法 |
|---|---|
| 不给资格结论 | 报告只写"要做什么/留什么/注意什么"，全文没有"你能获批""你不符合"；免责声明写死"不构成审批结论，也不构成法律意见" |
| 结论必须可复核 | 封面印 `ruleVersion` + 知识库 sha 前 12 位 + build；报告里每个数字都能追到规则（强积金上下限、续签窗口天数） |
| 政策会变 | 期限全部来自知识库而非硬编码；免责声明明确"政策调整会让排期失效，使用前核对官方" |
| 不夸大 | 金额一律写"估算/以积金局、税务局为准"；风险不承诺"必然通过审计" |
| 隐私 | 报告**全在本机生成**，不上传；只有用户主动下载才会落到磁盘 |

### 5.3 过程中修掉的 3 个真问题

1. **续签准备月算反了**：`segStart[m - prep]` 应为 `m + prep`（要在续签前 4 个月开始备料），否则报告里根本没有"准备月"，黄底一行都不出现。测试里加了"第 24 个月附近必须同时有准备与递交"的断言兜住。
2. **弹窗被浏览器拦掉**：自动化里 `window.open` 被拦后静默走了下载分支，报告"生成成功但看不到"。真机上点击是用户手势没问题，但探针必须带 `userGesture`，并且现在代码里 `window.open` 返回空时会**改为下载**（不会白点）。
3. **报告里 `</section>` 多余闭合**：拼 HTML 时手误多写一个闭合标签，浏览器容错看不出来，但打印分页会错位。已改成规整结构。

## 7. 复盘要点（给下一次）

1. **"够不够"要由引擎回答，不是让模型感觉**：`gaps()` 是三个必需字段的集合运算，模型不参与判断，所以不会出现"聊得很热闹但报告缺关键字段"。
2. **枚举点选 > 自由输入**：能点就不打字，既快又不会解析失败；但**同时保留**自由输入的路径，用户不想点就直接说。
3. **报告要能离线**：内联 CSS、无外链、下载脚本自己带，发给客户也能打开 —— 这是"可供用户下载"的实际含义。
4. **排期类产物必须可追溯**：封面印规则版本与知识库指纹，出问题时能定位到"哪一版规则排出来的"。
