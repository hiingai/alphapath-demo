## 0. 这一步到底解决了什么

P0 的库只在**各自浏览器**里，严格来说不算"汇总所有用户"。这一步把它补成真汇总：

> 每个用户的画像被**脱敏后上报**到服务端的轻量数据库（Cloudflare D1 / SQLite），
> 服务端**按同一套规则重算**分数与阶段，管理员登录后台就能看到**所有用户汇总后的**漏斗、分布、趋势与线索列表；
> 用户的删除权会同步落到汇总库（`deleted_at` + 清空联系方式）。

一句话链路：**对话 → 本机线索（P0）→ 出站队列（同意后）→ `POST /_api/ingest` → D1 → 管理员后台**。

## 1. 架构与选型

```
浏览器（静态站）                         Cloudflare（免费额度内）
┌───────────────────────┐               ┌────────────────────────────┐
│ 对话 / 档案（本地）      │               │  Worker: /_api/*           │
│ engine/leaddb.js       │  出站队列      │   ├ ingest（幂等 + 限速）    │
│   └ 线索（IndexedDB）    │ ───────────▶ │   ├ admin（登录/列表/改阶段） │
│  outbox（localStorage） │  批量 ≤50 条   │   ├ export.csv             │
│ admin.html（看板）       │ ◀─────────── │   └ lead-delete（删除权）    │
└───────────────────────┘   GET/PATCH    │  D1: alphapath（SQLite）    │
                                         └────────────────────────────┘
```

- **为什么是 D1**：轻量（就是 SQLite）、免费 5GB / 每天 500 万行读 / 10 万请求、单文件可导出（`wrangler d1 export`），
  以后要换 Supabase/Postgres，`schema.sql` 基本能 1:1 平移。
- **为什么不用自建服务器**：零预算 + 无运维，静态站本来就是 GitHub Pages。
- **同一份代码两种运行方式**：`worker/app.mjs` 在 Cloudflare 上跑 D1，在本地用 `node:sqlite` 冒充 D1 跑
  （`tools/dev_server.mjs`）。**测过的就是部署的**，不存在"本地一套线上另一套"。

## 2. 数据表（`worker/schema.sql`，已实施）

| 表 | 作用 | 关键点 |
|---|---|---|
| `leads` | 一条线索一行 | `lead_id` 主键（客户端派生 → 天然幂等）；`email_hash` 唯一索引去重；`intent_score/completeness/stage` **服务端重算**；`deleted_at` 软删留审计 |
| `events` | 上报流水 | `event_id` 主键 → 重复上传直接忽略（`INSERT OR IGNORE`） |
| `audit_log` | 管理员操作留痕 | 谁、什么时候、把阶段从什么改成什么 |
| `daily_metrics` | 每日聚合（预留） | 趋势目前直接 `GROUP BY substr(created_at,1,10)`，数据量大了再落表 |
| 视图 | `v_funnel` / `v_identity_mix` / `v_goal_mix` / `v_hot` | 给 SQL 直查与 BI 用，后台查询另走参数化语句 |

## 3. API（已实施）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/_api/health` | `{ok, build, db}`；前端用它判断"有没有汇总服务" |
| POST | `/_api/ingest` | `{token, events[]}`；token 16–64 位、事件 ≤50、body ≤64KB、单 IP 60 次/分 |
| POST | `/_api/lead-delete` | 用户自助删除，`token` 必须与线索的 `ext_user_id` 一致，否则 403 |
| POST | `/_api/admin/login` | 环境变量账号密码；成功返回 `HttpOnly Cookie` + `token`（跨域用 Bearer） |
| GET | `/_api/admin/overview` | 总数/留资率/高分/均值/阶段/身份/诉求/30 天趋势 |
| GET | `/_api/admin/leads?stage=&q=&sort=&limit=` | 服务端筛选，或前端拉 200 条本地筛 |
| GET | `/_api/admin/leads/:id` | 详情 + 事件流 |
| PATCH | `/_api/admin/leads/:id` | 只允许 `stage`（白名单）与 `note`，写审计 |
| POST | `/_api/admin/leads/:id/delete` | 软删 + 清空联系方式 + 审计 |
| GET | `/_api/admin/export.csv` | UTF-8 BOM，Excel 直开 |

**服务端不信任客户端结论**：上报里就算把 `intent_score` 写成 999、`stage` 写成 `converted`，落库前也会被
`scoreOf()/completenessOf()/stageOf()` 重算；人工阶段（已联系之后）不会被后续上报回退。

## 4. 客户端同步（`app.js`）

- **同意门控**：新增第二个勾选「同意把脱敏后的画像汇总到服务端」，**默认不勾**。不勾 = 一条都不上传，纯本机。
- **出站队列**：`localStorage['ap:outbox']`，每条 `{event_id, type:'lead.upsert', occurred_at, payload}`；
  `event_id = lead_id@updated_at` → 重试多少次都只算一次。
- **触发时机**：画像同步后、勾选/撤回同意、`online` 事件、每 60 秒、`pagehide` 用 `sendBeacon` 兜底。
- **只传结构化字段 + 证据片段 + 摘要**，通话原文（`ap:sessions*`）**永不出本机**；邮箱只在"同意联系"后才进 payload。
- **可见状态**：档案里一行小字实时显示「已汇总 19:24 / 待上传 3 条 / 汇总服务未连接（已排队）/ 汇总未开启」。

## 5. 后台鉴权（两种场景都覆盖）

| 场景 | 方式 |
|---|---|
| 同源（本地 dev、或 Worker 挂同域名） | 登录下发 `ap_admin` Cookie：`HttpOnly; SameSite=Strict`，12 小时 |
| 跨域（Pages 页面 → `*.workers.dev` API） | 登录返回签名 token，`sessionStorage` 保存，请求带 `Authorization: Bearer` |
| 未登录 | 所有 `/_api/admin/*` 一律 401；页面弹登录框，另给「看演示数据 `?demo=1`」入口 |

密码用环境变量（`wrangler secret put`），仓库里没有明文；登录接口 10 次/分限速。

## 7. 隐私与合规（这一步才真正涉及"出境/第三方处理"）

| PDPO 关注点 | 现在的做法 |
|---|---|
| 告知 | 勾选框写清"脱敏画像 / 不上传对话原文 / 用于改进服务与统计" |
| 同意 | 默认关闭；撤回后不再上传（队列保留在本机） |
| 最小化 | 只传身份、日期、受养人、学段、诉求、雇佣、轮次、摘要、≤120 字证据；不传账号密码、不传对话原文 |
| 查/改/删 | 档案页可导出 JSON；「删除我的留资」同时删本机 + 汇总库（`deleted_at` + 清空联系方式） |
| 保留期 | 尚未自动清理 —— **待你定 180 天匿名化还是物理删除**（cron 已可挂） |
| 跨境 | Worker 边缘节点在境外，属"跨境处理"；正式上线前需在隐私政策里写明并取得同意 |
| 安全 | 管理员密码走 secret、登录限速、管理接口 401、操作审计；联系方式字段的服务端加密**还没做**（见待办） |

## 8. 部署（5 分钟，免费额度内）

```bash
# 1) 建库
npx wrangler login
npx wrangler d1 create alphapath          # 把输出的 database_id 填进 wrangler.toml

# 2) 建表
npx wrangler d1 execute alphapath --remote --file=worker/schema.sql

# 3) 管理员账号（不要写进仓库）
npx wrangler secret put ADMIN_USER
npx wrangler secret put ADMIN_PASS
npx wrangler secret put ADMIN_SECRET      # 随便一串 32 位随机字符

# 4) 部署
npx wrangler deploy                        # 得到 https://alphapath-api.<子域>.workers.dev

# 5) 打开开关：编辑 sync-config.js
#    window.AP_SYNC_BASE = 'https://alphapath-api.<子域>.workers.dev';
#    然后 git commit + push，Pages 会自动发布
```

验证：`GET /_api/health` 返回 `{"ok":true,"db":true}`；控制台勾选"汇总"后，后台能出现该用户。

> 不填 `AP_SYNC_BASE` 也能用：Pages 上退化成"本机模式"，`admin.html?demo=1` 照样能演示（36 条虚构数据）。
> **但只要不部署 Worker，"汇总所有用户"就不成立** —— 这句必须跟投资人讲清楚。

## 10. 复盘：这一轮踩到的坑（已修）

1. **同一人变两条线索**：`syncFrom` 用原始大小写邮箱算 id，`buildLead` 内部用小写 → 大写邮箱会写到 A 键、查 B 键。
   现在统一在入口小写归一，测试连跑 3 次稳定。
2. **同意范围判断写错**：`consent_scope` 的值是 `both`，我一开始用 `.includes('contact')` 判 → 勾了"联系"却不加 15 分，
   分数 91 而不是 100。改成 `/contact|both/`，客户端/服务端口径才一致。
3. **对比度探针假阳性**：从父元素开始合成背景，漏掉按钮自身底色 → 把深底白字误报成白底白字。
4. **深色主按钮对比度 2.63:1**：白字改深色字，约 7:1。
5. **调试标签页污染数据**：旧页面残留 outbox 会补传旧账号。测试要清库 + 换干净浏览器 profile，否则会误判"重复写入"。

**给下次的规矩**：凡是"同一个概念在两处实现"（客户端算分 / 服务端算分），必须配一个**镜像断言**测试，
否则口径漂移只会以"分数怎么不一样"的形式在演示当天暴露。
