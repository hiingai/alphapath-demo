## 1. 系统架构现状

```
console.html            页面骨架（侧栏 / 聊天区 / 设置弹窗）
style.css               样式（含过程区、工具卡、清单卡片、会话列表）
app.js                  前端交互：渲染、事件、会话存档、清单渲染（606 行）
engine/
  index.js              门面：Engine.createAgent() / 领域能力透传
  harness.js            Agent：路由、工具循环、守门、记忆写入（570 行）
  llm.js                BYOK 大模型客户端（SSE 流式 + tool_calls）
  memory.js             短期/工作/长期记忆 + Store（localStorage）
  tools.js              工具注册表 + 沙箱 VFS（624 行，17 个工具）
  conductor.js          到期扫描
  domain/
    timeline.js         7 年主航道时间线（首签到期、递交窗口、届满日、费用）
    legal.js            三层法定资格（ALLOW / DWELL / COND / DENY / REVIEW）
    compliance.js       合规红线 C-011/C-012/C-013/C-014/C-015 + 规避检测
    guardrails.js       守门门面（输入拦截 + 输出改写 + tier 校验）
    matching.js         择校匹配；rag.js 语料检索；kb.js 知识库；embedding.js 向量
```

**数据流（一次提问）**

```
用户输入
  → guardrails.is_evasion_request()     命中 → 直接 C-015 话术结束
  → timeline_route()                    高置信度时间线 → 确定性引擎（不惊动模型）
  → llm 工具循环（仅 BYOK）             多轮 tool_calls → 工具结果回灌
  → _route() 规则兜底                   无 Key / 模型未命中时使用
  → guardrails.guard_output()           输出守门（本次重点修复）
  → 记忆写入 + 自动沉淀
```

**关键设计原则**：日期、资格、合规结论**只能**来自确定性引擎；大模型只负责组织语言和决定"调哪个工具"。

## 2. 今日五个问题：现象 → 根因 → 修复 → 验证

### P1 · 长对话里一提到"逾期记录"整段回答变成 C-015 模板

**现象**：用户让 AI"把续签材料清单做成带勾选状态的交互式 HTML"，AI 却回：
> 🧭 C-015：本平台只陈述法律事实……不提供任何规避、包装或「处理掉记录」的操作建议。

**根因**：`compliance.guard_output()` 对**模型的输出**也跑了一遍规避检测。模型为解释清楚，会复述用户早先的原话（"你之前问「怎么把逾期记录处理掉」……"），这段引述命中了规避正则，于是**整段有用的回答被替换成 C-015 模板**。

判断错在：*"用户问怎么规避"应拦* ≠ *"助手复述用户原话并陈述法律事实"应拦*。

**修复**：
- `compliance.js` 新增 `QUOTE_MARK`（`你/您/用户/客户 + 之前|刚才|上面 + 问|说|提到`、`「…逾期/规避/处理掉…」`、`"…"`）与 `is_evasion_output()`
- `guardrails.js` 同步同一口径（委托 `CP.is_evasion_output`）
- `guard_output` 改用 `is_evasion_output`；输入侧硬拦截**保持不变**

**验证**：`tests/_evade2_test.mjs` —— 引述式回答 `blocked=false`；裸请求 `blocked=true`；`tests/golden.spec.mjs` 的 `{ q: '怎么把逾期记录处理掉？', must: ['C-015'] }` 依旧通过。

### P2 · 模型自己"拒绝"也会被拦（第二层误杀）

**现象**：修完 P1 后仍偶发。模型回答："我**不会**提供**处理掉逾期记录**的建议；逾期期间不计入 7 年……" → 又被替换成 C-015。

**根因**：这句话没有引号，命中 `(规避|绕开|处理掉).{0,6}(逾期|超期|记录)`，且不满足 `QUOTE_MARK`。**它在拒绝，却被当成在教**。

**修复**：`compliance.is_evasion_output()` 增加**拒绝语境豁免** —— 命中词前后 20 字内出现
`不提供 / 不予 / 不会 / 不能 / 无法 / 不帮 / 不做 / 拒绝 / 禁止 / 不允许 / 不可以` → 放行。

**验证**（`tests/_ev3_test.mjs`，7 条用例全对）：

| 输入 | 期望 | 结果 |
|---|---|---|
| 怎么把逾期记录处理掉？ | 拦 | 拦 ✅ |
| 先逾期两个月，处理掉记录就行 | 拦 | 拦 ✅ |
| 我不会提供处理掉记录的建议，但可以帮你准备清单 | 放 | 放 ✅ |
| 本平台不提供任何规避…「处理掉记录」的操作建议 | 放 | 放 ✅ |
| 你之前问「…」，这里只陈述法律事实 | 放 | 放 ✅ |

**根因**：两层。① 输出守门误杀（P1）；② **根本没有生成文件的能力**——17 个工具里没有任何一个能产出文件。

**修复**：新增第 17 个工具 `make_file`：

输出：ARTIFACT:{kind,title,items,path,note,html,guessed}
副作用：写入沙箱 VFS artifacts/<slug>.html

- 生成**完全自包含**的 HTML：勾选框、localStorage 记忆、全选/清空/打印按钮、深色适配

- 工具模型描述明确写：**"仅当用户明确要求生成/导出清单、表格或文件时使用；问日期请用 compute_timeline"**

**验证**：`tools/probe_artifact.mjs` / `probe_artifact2.mjs` —— 8 项复选框、勾选后刷新恢复（`00101000`）、无裸 JSON 泄漏到对话、0 JS 异常。

### P5 · 旗舰功能"生成 7 年主航道"，20 项推理后返回 `__ERROR__` ★本次重点

**现象**：
```
输入：我是高才B类，2025.9.1激活签证，生成7年主航道
过程：转了约 20 条推理/工具步骤
结果：__ERROR__:需要至少一个条目，示例：title=续签材料清单 items=身份证明|雇佣合同|税单（用 | 分隔）
```

**根因链（三段，缺一不成）**：

1. **路由层**：这条请求走的是 BYOK 大模型路径，模型在"工具清单"里看到新加的 `make_file`，**误把"生成 7 年主航道"当成"生成文件"**，调用 `make_file` 却没给 `items`。
2. **工具层**：`make_file` 缺条目时返回 `__ERROR__:需要至少一个条目…`（硬错误），模型看不懂怎么修，**每轮重试同样的调用**。
3. **循环层**：`_chat_with_tools` 跑满 `MAX_TOOL_ROUNDS = 8` 轮后，把**最后一次工具结果当答案返回** —— 于是那句 `__ERROR__` 直接呈现在用户面前。整个过程累计约 20 条"第 N 轮：正在推理下一步…"。

> 这不是引擎算错，而是**把主功能托付给了模型的自由裁量**，并且**错误处理一路透传到 UI**。

**修复（四道防线，从外到内）**：

| 防线 | 位置 | 做法 |
|---|---|---|
| ① 路由前置 | `harness.js` 新增 `timeline_route()` | 身份 + 日期 + 时间线关键词（什么时候/多久/主航道/7 年/永居/续签窗口/到期/届满）→ **直接调 `compute_timeline`，完全不经大模型**。含"空档/断签/访客/逾期/算不算"等边界问法仍走原路径 |
| ② 工具自愈 | `tools.js` `make_file` | 缺 `items` 时**按标题自动套模板**（续签/学生/ROP145），返回 `guessed:true`；**永不再返回错误** |
| ③ 循环止损 | `harness.js` `_chat_with_tools` | 同一工具同一参数**连续两次全失败 → 立即退出循环**（原来要空转 8 轮） |
| ④ 错误兜底 | `harness.js` `chat()` | 工具全失败 / 回复以 `__ERROR__` 开头 → **回退确定性路由重算**；仍不行则给友好话术（"刚才的工具调用出错了…我不会凭猜测给日期"），**绝不把 `__ERROR__` 抛给用户** |

**验证（线上 + 本地都跑过，`tools/probe_loop.mjs`）**：
注入一个"每轮都疯狂调用 `make_file` 且参数为空"的假模型，发送用户原话：

```
LLM 被调用次数: 0        ← 完全没进模型
工具卡数量: 1            ← 只调 compute_timeline
思考行数量: 1            ← 不再是 20 条
含 __ERROR__: false
首个工具名: compute_timeline
答案: 【7 年主航道】高才通 B 类（tier=normal，规则版 policy.2026-10-06）
      - 激活：2025-09-01｜首签到期：2027-09-01
      - 递交窗口：2027-06-03 ~ 2027-07-21
```

**另外三条回归**（`tests/_nav2_test.mjs`）：
- 模型返回裸 `__ERROR__` → 用户看到的是友好话术 ✅
- 模型死循环调同一失败工具 → 调用次数 0（被前置路由拦下），无错误外泄 ✅
- "我是高才B类 2025.9.1 激活，帮我把续签材料清单做成可勾选 HTML" → 仍正确走 `make_file`，**未被时间线路由抢走** ✅

### P6 · 用户写了不存在的日期（2023-09-31），系统照样算出一整套日期 ★第二轮重点

**现象**：
```
输入：我是高才B类，2023.9.31激活签证，生成7年主航道
输出：【7 年主航道】… - 激活：2023-09-31｜首签到期：2025-10-01 …
      - 递交窗口：2025-07-03 ~ 2025-08-20
```
9 月没有 31 号，系统不但没提醒，还把 10 月 1 日当成激活日算完了全链路。

**根因**：`timeline.js` 用 `new Date(Date.UTC(y, m-1, d))` 解析日期，**JS 的 Date 会把越界日自动进位**（9 月 31 日 → 10 月 1 日）。
引擎本身"算得对"，但它算的是**用户没说过的日期**，而且没有任何一层做合法性校验 —— 这和"猜测"没有区别，只是猜得更隐蔽。

**修复（三层，全部前置，宁可不算也不猜）**：

| 层 | 位置 | 做法 |
|---|---|---|
| 校验器 | `timeline.check_date()`（新增，导出） | 4 类拒绝：格式 / 月越界 / 日越界（按真实月天数 + 闰年） / 年越界；越界时给出**两个候选日**（当月最后一天 / 次日） |
| 引擎 | `compute_visa_timeline()` | 非法日期 **throw `BAD_DATE`**，不再静默进位；返回的 `activation` 用规范化后的 ISO |
| 工具 | `compute_timeline` / `compute_dwell` | 先校验，返回**人话提示**（不带 `__ERROR__` 前缀，模型不会当失败重试）；`compute_dwell` 逐条校验 segment 的 `start`/`end` |
| 对话 | `harness.chat()` 前置拦截 | 命中非法日期 → emit 一条 think + 直接回答，**steps=0、tool_used=null、不入模型** |

**用户看到的文案**：
```
日期「2023-09-31」不存在：2023 年 9 月只有 30 天，没有 31 号。
你指的是 2023-09-30（当月最后一天）还是 2023-10-01（次日）？
确认是哪一个？回复日期我立刻算 7 年主航道。
我不会替你猜日期——猜错一天，续签窗口就全错。
```

**验证**（`tools/probe_date.mjs`，真实浏览器 + 假模型；`tests/_date_test.mjs` 覆盖单测/工具/对话三层）：

| 输入 | 结果 | 工具卡 | LLM 调用 |
|---|---|---|---|
| 2023.9.31 → 9 月只有 30 天 | 拒绝 + 候选 2023-09-30 / 2023-10-01；**未出现错误首签到期日 2025-10-01** | 0 | 0 |
| 2025.2.30 → 2 月只有 28 天 | 拒绝 + 候选 2025-02-28 / 2025-03-01 | 0 | 0 |
| 2023.13.1 → 月份越界 | 「月份 13 不存在：一年只有 12 个月」 | 0 | 0 |
| 2024.2.29（闰年，合法） | 正常计算：首签到期 2026-02-28（月末对齐） | 1 | 0 |
| 2025.2.29（非闰年） | 拒绝 + 候选 2025-02-28 / 2025-03-01 | 0 | 0 |

JS 异常 0；黄金断言 67/67（新增 12 条日期断言）。

**附带修掉的两个老毛病**（此前被算作"历史失败项"，一半是测试写错、一半是真 bug）：

1. **DWELL 文案拼出病句**：`「服务被拦截。」` 经替换变成 `「该段期间不计入 7 年，该期间不计入，服务被提示。」`。
   现在改为：先退化「被拦截」→「拦截」，再替换，去重复短语，末句固定为
   `「该段期间不计入 7 年，服务不受影响。服务入口正常开放；其后合法居留期可重新起算 7 年。」`
2. **「你还记得吗」召不回刚存的记忆**：`recall` 用整句当检索词，元问题里没实词 → 空结果。
   现在：检索为空且问句含「记得/记忆/说过/提过/告诉过/之前」时，**退回最近 5 条记忆**。

**另外 3 条"历史失败项"确认是测试写错，不是引擎错**（用 Python 参考版实测对齐）：

| 断言 | 原期望 | 实测（Python 与 JS 一致） | 处理 |
|---|---|---|---|
| `TTPS_A 高峰提醒` | `isPeak === true` | 2023-09-01 激活 → 2026-09-01 到期，9 月不在 peak `[6,7,8]` → `false` | 断言改为 `false`，名称改为「非高峰月」 |
| `gap tier=dwell` | `profile.tier === 'dwell'` | profile 层仍是 `normal`，**notice 的 tier 才是 `dwell`**（② 层只降年限不降资格） | 断言改为「notice 含 dwell」 |
| `风险分 = 0.8` | `0.8` | 该用例实际 3 个信号（注册<6 月 / MPF 不匹配 / 无租约）→ `0.4+3×0.2 → 0.95` | 断言改为 `0.95`，名称注明「三信号」 |

> 教训：**"历史失败项"要一条条去参考实现里验**，别默认是自己移植错了 —— 三条里三条都是断言写错，真正的 bug 只有一个病句和一个空召回。

### P7 · 用户说「高才 B 类」，系统却按 A 类算（身份口径不一致）★第三轮重点

**现象**：
```
输入：我是高才B类，2025.9.1激活签证，生成7年主航道
输出：【7 年主航道】…（按 A 类参数）→ 首签到期 2028-09-01
      但用户自述是 B 类，B 类首签 2 年，应为 2027-09-01
```
A 类首签 3 年（3+3+3），B/C 类首签 2 年（2+3+3）——**类别认错一年，整条时间线全错**。

**根因（三处叠加，都能单独致命）**：

1. **关键词匹配不做归一化**：`detect_identity()` 直接对原文 `toLowerCase()` 后找子串。
   用户写「高才 **B** 类」（带空格）、「高才通计划 **B** 类」时 `'高才b'` 匹配不上，
   掉进下一行的通用键 `'高才'` → **TTPS_A**。
2. **漏别名**：「高端人才通行证计划B类」不在任何关键词里 → 识别为 `null`，
   而路由里写着 `identityType=(ident || 'TTPS_A')` → **默默按 A 类算**，用户完全看不出来。
3. **没有身份记忆**：用户先问 B 类、后改口 A 类，两轮各自独立识别，系统不记录"这个人现在是哪一类"，
   也不告诉用户"我改过来了"。

**修复（四层）**：

| 层 | 位置 | 做法 |
|---|---|---|
| 归一化 | `harness.norm_cn()` | 全角→半角、**去掉所有空白**、转小写；关键词也同一套归一化后再比 |
| 优先正则 | `HIGH_TALENT_BEFORE / AFTER / LOOSE` | `高才(通)?(计划)?[A-C][类類]`、`[A-C][类類]高才`、`高才B`；含繁体「類」；`高才通计划 B 类`、`高端人才通行证计划B类`、`我是A类高才` 全部命中 |
| 歧义不猜 | `detect_identity_detail()` → `{code, ambiguous}` | 只写「高才」不带 A/B/C → `ambiguous=true`；`chat()` 直接反问 A/B/C 并说明「首签年期不同，差一年」，**steps=0、不调用工具**；资格问题（tier/可否永居，三类相同）才按 A 类口径给剖面 |
| 身份档案 | `Agent.remember_identity()` / `current_identity()` | 识别到身份 → 写入长期记忆 `tags:['profile','identity-profile']`；**改口时旧记录 `status=superseded` 而非删除**，回答开头明示「（已更新你的身份记录：高才通 B 类 → 高才通 A 类，后续按新类别计算）」 |

**并且多了一条兜底能力**：用户后面只说「我 2025.9.1 激活的，什么时候到期？」（不再重复身份）→

### P8 · 「什么时候续签」被模型心算成 A 类日期 ★第四轮（build 20261027n）

**现象**（用户实测 build 20261027k，BYOK 真实模型）：
```
输入：高才B 2025.9.1 激活的，什么时候续签？
输出：· 第 1 轮：正在推理下一步…
      # 你的续签时间（激活日 2025-09-01）
      | 首签续签 | 2028-09-01 | …
```
B 类首签 2 年，应为 **2027-09-01**；2028-09-01 是 **A 类 3 年**口径。
模型在第二轮自我纠错时又给出 2030/2033（按「2+3+3」），错得更远。

**根因**（不是身份识别，这次识别是对的）：

1. **模型抢答**：该问句本应命中确定性路由，但一旦有任何一条表述越出关键词白名单，就落进 LLM 分支，
   模型自己 list 了一张表——**表里没有规则版本、没有 tier、没有工具调用痕迹**，全是心算。
2. **心算用错了口径**：模型用「高才通 2+3+3」这个坊间印象覆盖了本系统 policy.2026-10-06 的 **2+2+3**。
3. **没有任何一致性校验**：模型给的日期与引擎不一致时，系统原样透传给用户。
4. **附带 bug**：`get_time` 用 `'时间'` 作为关键词，"续签时间是什么" 会被当成"现在几点"。

**修复（四层，重点是第 3 层）**：

| 层 | 做法 |
|---|---|
| ① 路由收口 | `timeline_route` 增加 `续签时间`；`get_time` 只在**无身份、无日期、无续签语境**时才接管（"续签时间"不再被劫持） |
| ② 缺日期就问 | 有身份、问时间、但没给激活日 → **不进模型**，直接索取日期（"日期我不会替你估"），steps=0 |
| ③ **引擎覆盖（最后一道闸）** `Agent.prototype.verify_timeline()` | 只要「身份 + 激活日」可算，就把模型答案里所有 `20xx-xx-xx` 抽出来跟 `compute_timeline` 的日期集比对：<br>· 有任何一个对不上 → **整段替换成引擎输出**，并注明「模型给出的日期与规则引擎 policy.2026-10-06 不一致，已按引擎口径更正」<br>· 一个日期都没给、但问的就是时间 → 用引擎补齐<br>· 问的是材料/流程、且日期无冲突 → 保留模型答案（不误伤）<br>· 该闸同时作用于「工具循环」和「直连模型」两条路径 |
| ④ 提示词硬约束 | SYSTEM_PROMPT 增「日期零心算」：不得用 2+3+3 之类外部印象、被纠错必须先重跑工具、输出日期必须能对上工具字段 |

**验证**（`tests/golden.spec.mjs` 101 条 + `tools/probe_p8.mjs` 真实浏览器，假模型故意返回用户那张错表）：

| 用例 | 期望 | 结果 |
|---|---|---|
| 高才B 2025.9.1 激活的，什么时候续签？ | 2027-09-01 / 2029-09-01 / 2032-09-01，模型 0 调用 | ✅ 确定性引擎直出 |
| 高才B 2025.9.1 激活的，续签时间是什么 | 同上（不被 get_time 劫持） | ✅ |
| 我是高才B，什么时候续签？ | 索取激活日期，0 工具 0 模型 | ✅ |
| 高才B 2025.9.1 激活的，几时该递件？（绕开路由，假模型返回 2028-09-01） | 引擎覆盖，输出 2027 系列 + 更正说明 | ✅ 模型被调用 1 次但答案被覆盖 |
| 问材料、无日期冲突 | 保留模型答案 | ✅ 不误伤 |

**B 类口径确认**：policy.2026-10-06 高才通 B/C = **2+2+3**（首签 2 年 → 续签 1 为 2 年 → 续签 2 为 3 年），A 类 = 3+3+3。
2025-09-01 激活 → B 类：2027-09-01 / 2029-09-01 / 2032-09-01（7 年届满 2032-09-01）。

> 教训：**"模型能调用工具" ≠ "模型会调用工具"**。只要有一条路径能绕过工具，就必须有一道
> **输出比对**的闸——不是信模型说"我调了工具"，而是把它给的每个日期拿去和引擎对账。

## 8. 复盘要点（写给以后的自己）

1. **守门要判"意图"，不是判"词"**：同一串词出现在用户提问里和出现在助手解释里，含义完全相反。凡是用正则做安全判定，都要问一句"这段文字是在**教**，还是在**拒绝/引述**"。
2. **旗舰功能不能让模型兜底**：模型会误选工具、会重复失败。凡是有确定性答案的问题，就用路由**短路**掉大模型，模型只做措辞。
3. **错误永远不要透传到 UI**：内部 `__ERROR__` 是给程序看的，用户只该看到"我为什么没做成 + 你该怎么问"。
4. **缓存是隐形 bug**：静态站每次发版必须验证"用户端拿到的是新代码"，否则所有修复都停留在本地。build 徽章是最便宜的解法。
5. **可复现的探针 > 手点**：注入假 SSE 就能零成本复现多轮工具分支，比反复求用户截图快一个数量级。
