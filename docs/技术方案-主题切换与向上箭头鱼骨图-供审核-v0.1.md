## 0. 一句话结论

> 界面从「只有深色」改为**浅色为默认、深色一键可切**，做法不是加滤镜，而是把 40+ 处写死色值

## 2. 主题化（R1）

### 2.1 为什么必须做 token 重构

原 `style.css` 是「深色写死」：颜色以字面量散落在约 200 处（`#0b1220`、`#4da3ff`、`rgba(...)`）。
若用「CSS 滤镜 / 反色」实现浅色，会出现：品牌色失真、图片与阴影反转、渐变发灰、可读性不可控。
因此改为**语义 token 层**：

```css
:root {                       /* 浅色：默认 */
  --bg:#f4f7fb; --panel:#ffffff; --panel-2:#f8fafd; --inset:#eef3fa;
  --text:#16202e; --muted:#5b6b7f; --faint:#6b7d92;
  --brand:#2b7de0; --ok:#12996a; --warn:#b3760f; --bad:#d64545;
  --line: rgba(20,40,70,.12); --line-soft: rgba(20,40,70,.08);
  --shadow: 0 6px 18px rgba(20,40,70,.08);
  /* …surface-1/2/3、bubble-user、avatar-*、overlay、danger-*、on-brand、on-accent … */
}
:root[data-theme="dark"] {    /* 深色：沿用原值，保证老观感不退化 */
  --bg:#0b1220; --panel:#111a2b; --text:#e8eef7; --brand:#4da3ff; /* … */
}
```

覆盖的 token 族群（共 40+）：

- 表面：`--bg` `--panel` `--panel-2` `--inset` `--surface-1/2/3` `--surface-active` `--avatar-bg`
- 文字：`--text` `--ink` `--ink-2` `--ink-3` `--ink-strong` `--muted` `--muted-2` `--faint` `--label`
- 线条：`--line` `--line-soft` `--line-strong` `--dot-line` `--ok-line` `--bad-line` `--brand-line` `--danger-line`
- 语义色：`--brand` `--brand-2` `--brand-light` `--brand-soft` `--ok` `--ok-2` `--ok-soft` `--warn` `--bad` `--bad-2` `--danger-bg` `--danger-text`
- 前景反色：`--on-brand`（用在深色按钮上永远是白字）、`--on-accent`（浅底上的强调字：浅色 `#0f3f72` / 深色 `#dbe8f8`）
- 其它：`--shadow` `--overlay` `--spine` `--spine-2` `--brand-grad-2` `--toggle-on-text`

### 2.2 防闪：先落属性，再加载样式

`console.html` 的 `<head>` 里、样式表之前插入内联脚本：

```html
<script>
(function () {
  var t = 'light';
  try { t = localStorage.getItem('ap:theme') === 'dark' ? 'dark' : 'light'; } catch (e) { }
  document.documentElement.setAttribute('data-theme', t);
})();
</script>
```

时序：HTML 解析 → 立即定 `data-theme` → 之后才解析 CSS → 首帧就是正确主题。
（若放在 `app.js` 里做，会有 1–2 帧的深色闪屏。）

### 2.3 切换入口与持久化

- 顶栏新增按钮：`<button id="themeBtn">🌙 深色 / ☀️ 浅色</button>`，与 🐟 按钮同款 `.btn.ghost.small`；
  ≤560px 只留图标（`.tlabel { display:none }`）。
- `app.js`：

```js

function applyTheme(mode, announce) {           // 写 data-theme + localStorage + 按钮文案
  var t = mode === 'dark' ? 'dark' : 'light';

  localStorage.setItem(THEME_KEY, t);
  …按钮文案/提示…
}
function currentTheme() { … }
function initTheme() {                          // boot() 内调用，默认 light
  var saved = localStorage.getItem(THEME_KEY);
  applyTheme(saved === 'dark' ? 'dark' : 'light', false);
  $('themeBtn').addEventListener('click', …切换 + appendNotice…);
}
```

### 2.4 浅色下的「踩坑修正」

| 现象 | 根因 | 处理 |
|---|---|---|
| `.chip:hover`、`.icon-btn:hover` 在浅色下白字白底 | 悬停态用了 `--on-brand`（纯白），而浅色悬停底是浅灰 | 新增 `--on-accent`，浅色深蓝、深色近白 |
| `--faint` 元信息字对比度 2.79–2.97 | 浅色下灰度过亮 | 浅色 `--faint` 收到 `#6b7d92`、`--muted-2` → `#6d7f94`、`--label` → `#41536a` |
| 右侧鱼骨面板阴影在浅底上「脏」 | 深色阴影用在白底 | 单列 `:root[data-theme="light"] .fishpanel { box-shadow: -8px 0 24px rgba(20,40,70,.06) }` |

## 3. 鱼骨图改版（R2–R5）

### 3.1 结构（DOM）

```html
<div class="fish">
  <i class="arrowhead"></i>        <!-- 顶部三角箭头：向上 = 进度方向 -->
  <div class="spine">              <!-- 主脊 10px，从底部生长 -->
    <i class="fill" style="height:17%"></i>
  </div>
  <div class="today" style="bottom:17%"><span>今天</span></div>
  <ul class="bones">               <!-- column-reverse：DOM 第一条 = 最底部 -->
    <li class="bone left done">…开始申请…</li>
    <li class="bone right done">…签证激活…</li>
    …
    <li class="bone left future finish">…7 年届满…</li>
  </ul>
</div>
```

### 3.2 关键 CSS 决策

| 目标 | 实现 | 说明 |
|---|---|---|
| 主脊加粗 5 倍 | `.spine { width:10px; left:8px; border-radius:6px; background:var(--spine-2) }` | 原 2px；内加 1px `inset` 环，避免白底上「糊成一条」 |
| 时间从下往上 | `.bones { display:flex; flex-direction:column-reverse }` | **不动 JS 排序**（节点仍是升序数组），只反渲染方向；避免与引擎排序口径分叉 |
| 进度从底部涨 | `.spine .fill { position:absolute; bottom:0; height:0; transition:height .5s }` | 由 `progressPct` 直接给 `height` |
| 箭头 | `.arrowhead`：左右 13px 透明边框 + 20px 底边 `--brand` + `drop-shadow` | 纯 CSS 三角，无图片 |
| 今天刻度 | `.today { position:absolute; left:22px; right:8px; border-top:1px dashed var(--ok-2) }`，`bottom:progressPct%` | 只在 2% < pct < 98% 时渲染，避免贴边 |
| 斜骨 | `.stem` 35px 宽、`rotate(-22deg)`（`.left` 反转 `22deg`），按状态取色 | 保留原「鱼骨」语义，但改成更短更粗以适应 10px 主脊 |
| 活跃感 | `@keyframes boneIn`（位移+淡入，`nth-child` 0.02s 起逐条延迟）、`.fdot.current` 呼吸环 `fpulse`、`.fnode:hover` 抬升 | 纯 CSS，无 JS 定时器 |
| 状态可读 | `.bone.done` 绿边、`.current` 品牌边框 + 阴影 + `.flabel::after{content:"进行中"}`、`.finish .flabel` 绿色 | 颜色之外还有**文字标签**，不只靠颜色区分 |

### 3.3 数据层：新增可选「开始申请」节点

`engine/domain/fishbone.js`（改动集中在 `build()`）：

1. 校验：`AP.timeline.check_date(opt.applyDate)`；非法 → `{ok:false, reason:'BAD_APPLY_DATE'}`（与 `BAD_DATE` 同族，前端可分辨）。
2. 顺序校验：申请日 > 激活日 → 追加 warning「开始申请日期晚于签证激活日，顺序反了，请核对」，**不报错、不阻断**。
3. 等待期说明：否则追加 warning「从递交申请到签证激活：N 天（这段等待不计入 7 年）」。
4. 插入节点（在激活节点**之前**）：

```js
{ key:'apply', label:'开始申请', kind:'apply', bone:'left',
  detail:'递交申请（等待期不计入 7 年）', date: applyIso,
  status: today >= applyIso ? 'done' : 'future' }
```

5. 激活节点 `detail` 改为 `'7 年起算点'`，`status` 按「今天 vs 激活日」判定。
6. 返回值新增 `applyDate`；**`progressPct` 仍只由「激活日 → 7 年届满」计算**——申请日不参与任何推算。

> 口径理由：7 年通常居住期从**入境激活/首次入境**起算，递交申请到获批/激活的等待期不计入。
> 因此「开始申请」是**叙事节点**，不是计算节点；标注 `detail` 与 warning 双重提示，避免用户误以为能「提前起算」。

### 3.4 前端渲染

`app.js` 的 `renderFish()` 重写要点：

- 先追加 `.arrowhead`，再 `.spine > .fill`，再 `.today`，最后 `.bones`（z 序与定位都依赖这个顺序）。
- 节点 `li` 的 class 拼装：`bone {left|right} {done|current|future} [finish]`；`kind==='apply'` 加 📝，`start` 🛫，`finish` 🏁。
- `fishState` 增加 `applyDate`，与 `identityType/activationDate` 一起 `saveFish()` 持久化；
  存储键改为 `scoped('ap:fish')`（见任务 2 的账号隔离，未登录时等价于原 `ap:fish`）。
- 输入框为空态：`fishApply.value = fishState.applyDate || ''`，并在切换时回写提示语。

### 3.5 空态/异常态（未变，仍守「宁可不算」）

| 情形 | 面板表现 |
|---|---|
| 缺身份 | ①②③ 填写引导（选身份 / 填激活日 / 自动推算） |
| 缺激活日 | 同上；`BAD_DATE` 由 `type=date` 天然拦截 |
| 身份不产生永居（外佣、输入劳工等） | 只给结论「不产生 7 年永居路径，骨图不需要画——这本身就是结论」，**不要求填表** |
| 非法申请日 | 面板警告提示，不影响主链路（API 层返回 `BAD_APPLY_DATE`） |

## 5. 风险与已知限制

| # | 风险 | 说明 / 缓解 |
|---|---|---|
| 1 | **浅色是新增配色，非原始设计** | 已用「自动化对比度扫描」兜底（<3:1 归零），但审美仍需人眼确认；`--brand` 等锚点可按品牌手册再调 |
| 2 | 深色配色沿用旧值，未做同强度对比度审计 | 扫描结果 0 低分项，但仅覆盖当前渲染出的元素（折叠态、错误态需单独触发） |
| 3 | 鱼骨「开始申请」易被误解为可提前起算 | 节点 `detail` + warning + 面板文案三处说明；`progressPct` 明确不参与 |
| 4 | `column-reverse` 依赖 JS 已按日期升序 | 若未来 JS 改为降序，渲染方向会整体反转；已在 `fishbone.js` 注释与本节标明契约 |
| 5 | 主题偏好按浏览器存，不随账号走 | 属刻意选择（设备级偏好）；若要跟随账号，需并入 `userdb` 档案（见任务 2 文档 §6） |
| 6 | `index.html`（营销页）仍是深色单文件 | 本次范围外；如需统一，需另做一轮 token 化 |
