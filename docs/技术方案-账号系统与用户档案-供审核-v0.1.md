## 0. 一句话结论

> 在纯静态站（GitHub Pages，无后端）上落地了**可用的账号系统**：邮箱注册/登录，密码经
> **PBKDF2-SHA256（12 万次迭代）+ 16 字节随机盐**派生后**只存摘要**；手机号验证码与微信登录
> **接口已预留、按钮灰置标「即将开放」**；账号数据全部在本机 **IndexedDB**（单库三表 `users / facts / turns`）。
> 登录后**会话记录与鱼骨状态按账号命名空间隔离**（`ap:sessions:u:<userId>`、`ap:fish:u:<userId>`），
> 退出登录进入访客空间互不可见；同时把对话里的事实**确定性抽取**进 `facts` 表，形成「用户信息库」的雏形。
> 存储层抽象成 adapter，将来接真后端**只换 adapter，不动调用方**。

## 3. 数据模型

### 3.1 `users`

```js
{
  id: 'usr_xxxx',            // uid('usr_')
  email: 'demo@alphapath.hk',
  emailLower: 'demo@alphapath.hk',   // 唯一索引，用于查重
  name: '陈先生',                     // 缺省取邮箱前缀
  pw: { algo:'PBKDF2-SHA256', iter:120000, salt:'<32 hex>', hash:'<64 hex>' },
  providers: { phone: null, wechat: null },   // 预留
  createdAt: '2026-10-30T…'
}
```

- **绝不存明文**：`pw.hash` 是 `deriveBits(PBKDF2-SHA256, salt, 120000, 256bit)` 的 hex；探针直接读 IndexedDB 断言 `JSON.stringify(user)` 不含明文密码。
- 无 `crypto.subtle` 的环境（Node 沙箱等）降级为「加盐迭代 SHA-256（≤2000 轮）」，浏览器永远走 PBKDF2。
- `SESSION_KEY='ap:auth:token'`、`CURRENT_KEY='ap:auth:user'` 只存**脱敏快照**（无 `pw`）。

### 3.2 `facts`（用户信息库雏形）

```js
{
  id: '<userId>|<key>',      // 复合主键：同一用户同一事实只有一条有效记录
  userId, key, value,
  confidence: 1, source: 'conversation' | 'user' | 'rebuild',
  updatedAt, superseded: false,
  history: [{ value:'TTPS_B', at:'…' }, …]   // 改口留痕，保留最近 8 条
}
```

事实字典（`FACT_DEFS`）：`identityType 身份类型`、`activationDate 签证激活日`、`dependants 受养人`、
`schoolStage 孩子学段`、`employment 雇佣情况`、`goal 主要诉求`。

- **单一事实表语义**：`set()` 先查有效记录；值相同只更 `updatedAt`；值不同则新记录 `history` 追加上一条并 `superseded` 旧记录（与引擎侧短期记忆 supersede 口径一致）。
- `clear(key)` 不是物理删除，而是 `superseded = true`（可审计、可回溯）。

### 3.3 `turns`（预留）

表已建好（`userId` 索引），当前未写入；任务 3 用于「按用户存对话轮次摘要」以避免与 `localStorage` 会话重复存储。

## 4. 认证流程

### 4.1 注册

```
校验邮箱格式 → 校验密码长度(≥8) → findByEmail 查重
 → randomSalt(16B) → derive(pw) → users.put()
 → _settle(user)：只把 {id,email,name,createdAt,providers} 写 localStorage
 → 前端：onAuthChanged({adoptGuest:true}) → profile.rebuild(会话, 长期记忆) → 提示「已建立档案 N 项」
```

错误文案（人话，非 code）：`邮箱格式不对` / `密码至少 8 位` / `这个邮箱已经注册过了，直接登录吧`。

### 4.2 登录

```
findByEmail → derive(pw, user.pw.salt, user.pw.iter) → 与 hash 比对 → _settle
```

错误：`没找到这个邮箱，先注册` / `密码不对`。

### 4.3 手机号 / 微信（预留）

```js
loginWithPhone(phone, code) → Promise.reject(Object.assign(new Error('手机号登录尚未开放（接口已预留）'),
                                   { code:'NOT_ENABLED', mode:'phone', mock:{phone, code} }))
loginWithWeChat(payload)   → 同上（mode:'wechat'）
loginModes() → [
  { id:'email',  enabled:true,  note:'本机注册，密码经 PBKDF2 派生后只存摘要' },
  { id:'phone',  enabled:false, note:'预留接口：接短信服务商后开启' },
  { id:'wechat', enabled:false, note:'预留接口：接微信开放平台后开启' }
]
```

UI 侧：按钮 `disabled` + `.soon` 徽标「即将开放」，点击只回显提示（保留点击可达性以便演示接口形状）。
接真通道时只替换这两个函数体（发码 / OAuth 回调 → 建或找用户 → `_settle`）。

## 5. 账号与会话的隔离

### 5.1 命名空间

```js
function uidScope() { … return user ? user.id : ''; }
function scoped(base) { var u = uidScope(); return u ? base + ':u:' + u : base; }

localStorage['ap:sessions']            // 访客空间
localStorage['ap:sessions:u:usr_xxx']  // 某账号
localStorage['ap:fish'] / 'ap:fish:u:usr_xxx'
```

- 未登录 = 访客空间（键与改动前完全一致，**老用户数据不丢**）。
- 登录态变化统一走 `onAuthChanged()`：重载 `sessions` → 重渲染左栏 → 重载鱼骨状态 → 打开最近一条会话，否则回到欢迎页。

### 5.2 访客会话「收编」

```
登录/注册成功 && 账号空间为空 && 访客空间有会话 → 整段搬到账号空间，并删除访客键
```

- **只在账号空间为空时**合并，绝不覆盖账号已有数据；
- 提示里明说「已把本机 N 条对话收进你的账号」，避免用户以为是自动同步。

### 5.3 退出登录

- 只清 `ap:auth:*`，**不删数据**；界面回到访客空间（实测：退出后左栏 0 条、聊天区回到欢迎页）。
- 重新登录 → 对话原样回放（实测：会话 1 条、消息 3 条，与退出前一致）。

## 6. 用户档案（用户信息库雏形）

### 6.1 抽取（确定性规则，不调模型）

`profile.extract(text)` 复用引擎既有确定性能力：

- 身份：`AP.Agent.detect_identity(text)`（含别名归一、`高才(通|计划)? [ABC] 类`、全角/空白归一）
- 激活日：`AP.Agent._detect_date(text)`
- 受养人：`/([1-5一二两三四五])\s*(?:个|名)?\s*(?:孩子|小朋友|子女|仔女|小孩)/`
- 学段：`中一…中六 | 初中 | 高中 | DSE | 小一…小六 | 小学`
- 雇佣：`自雇|自己开公司|老板|创业` → `self-employed`；`受雇|打工|上班` → `employed`
- 诉求：`永居/永久居民` → `pr`；`续签` → `renewal`；`择校/学校/学位/插班` → `school`

### 6.2 三个写入时机

| 时机 | 调用 | 说明 |
|---|---|---|
| 每轮用户消息 | `learnProfile(text)` → `profile.learn()` | 静默、失败不影响对话；只写有变化的键 |
| 注册成功 | `profile.rebuild(sessions, memories)` | 用历史对话 + 长期记忆按时间顺序重放，后说的覆盖先说的 |
| 手动 | 「我的档案」→「从对话重建档案」 | 用户可随时纠正 |

### 6.3 展示与纠错

- 「我的档案」视图列 5 类事实：标签 + 值（身份显示中文名、雇佣/诉求显示人话），**每行可 ✕ 单独清除**。
- 后续任务 3 计划：值可直接编辑、展示 `history`（改口轨迹）、`asContext()` 注入系统提示。

### 6.4 `asContext()`（已实现，任务 3 接线）

输出形如：

```
【用户档案（来自历史对话，可能过时）】
- 身份类型：高才通 B 类
- 签证激活日：2025-09-01
- 受养人：2
…
```

刻意带「可能过时」四字：档案是**提示**，不是结论；任何日期/资格仍必须走引擎重算。

## 8. 风险与已知限制

| # | 风险 | 说明 / 缓解 |
|---|---|---|
| 1 | **账密只在本机**，换设备/清缓存即「账号不存在」 | 静态站无后端，属设计边界；UI 已明写「数据只存在这台设备」。要跨设备必须接后端（adapter 已留口） |
| 2 | 本机 IndexedDB 可被同机他人用开发者工具读取 | 只存摘要不存明文；提示「公共电脑请勿注册重要密码」；不承担身份验证职责 |
| 3 | 无「忘记密码 / 改密码 / 注销账号」 | 无邮件通道，无法做找回；可在任务 3 补「改密码（验旧密）+ 删除账号」 |
| 4 | `localStorage` 与 IndexedDB 可能不一致（用户清一半） | `current()` 读到脏数据仅影响顶栏展示，`auth.login()` 仍以 IndexedDB 为准 |
| 5 | 会话隔离是**键级**而非加密 | 同一浏览器内可被绕过（改 localStorage）；定位为「体验隔离」，不是安全隔离 |
| 6 | 访客会话收编是**单向一次性** | 只在账号空间为空时发生；之后不再自动同步，避免误合并 |
| 7 | 档案抽取是正则规则，覆盖有限 | 认不出的说法不会瞎写（宁缺勿错）；`history` 保留改口痕迹，用户可手动清 |

## 10. 待审核确认项

1. **账号的作用域**：确认为「本机体验账号」还是需要「跨设备真账号」？后者要接后端（最低成本：一个 Serverless 函数 + KV/SQLite），前端改动量约 1 个 adapter。
2. **是否需要「改密码 / 删除账号」**？删除账号要连同 `facts`、会话命名空间一起清（建议给「导出 JSON 再删」）。
3. **档案是否注入系统提示**（任务 3 核心）？注入后模型能「记得你」，但也可能把过时事实当结论——我的建议是注入 + 强制「日期仍须重算」的提示词约束。
4. **手机号/微信**接入优先级与合规（短信模板、微信开放平台主体），以及是否需要「手机号 + 密码」而非仅验证码。
